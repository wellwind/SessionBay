# OpenCode synthetic fixtures

All text, IDs, paths and timestamps are synthetic. Tests build SQLite databases (and WAL files) in temporary directories. No real history, credentials or logins are used.

- **[schema.sql](schema.sql)** is a hand-authored reader subset of the reviewed OpenCode 2.2.3 `session_v2`, `session_message` and `session_part` tables. It contains no 1.x tables.
- **[cli-2.2.3-migrated-from-1.19.5.sql](cli-2.2.3-migrated-from-1.19.5.sql)** is an official macOS arm64 CLI 2.2.3 SQL dump after migrating a synthetic CLI 1.19.5 database. The original seed was generated using official 1.19.2/1.19.3 binaries; the seed fixture was removed with CLI 1.x support. The official 1.19.5 and 2.2.3 binaries ran in isolated HOME and XDG directories; release archive digests matched GitHub releases. The retained 1.x tables stay in this fixture to prove they are ignored, including IDs absent from `session_v2`. Migrated `session_v2` rows retain their original reviewed 1.x versions and remain fully readable. `session_message` includes 2.x system notices; `session_part` is empty. This verifies migration, not native 2.x model-generated parts.
- **[export-cli-2.2.3.json](export-cli-2.2.3.json)** is the real export from that isolated synthetic run. It documents the 2.x export format; tests use fake CLIs and synthetic exports for cleanup and restore.
- Native 2.x rows in `src-tauri/tests/opencode.rs` follow the reviewed v2.2.3 sources: `packages/core/src/session/sql.ts`, `session/history.ts`, `session/projector.ts`, and `packages/schema/src/session-message.ts`. They cover part precedence and ordering, inline fallback, version gates, NULL titles, safety limits and recursive cleanup. They are not native model-run captures.
- Negative tests create malformed schemas, JSON, SQLite/WAL files, sequence conflicts, reverts, and databases without `session_v2`. The last case verifies a non-fatal migration message without source writes. Legacy export records are synthesized to verify that restore preserves their files and records without any CLI call.

The reader never reads `session`, `message`, `part`, or the old 1.x `session_message` projection. Only a 2.x CLI is supported for live state, cleanup and restore.
