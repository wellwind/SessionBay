## 來源與工具

每個 Agent 有自己的設定：

- **啟用**你用到的 Agent。停用的 Agent 會保留已索引的歷史，但不會掃描或啟動。
- **執行檔路徑**：Session Bay 會在常見的安裝位置尋找。macOS 的 App 不會繼承 Shell 的 `PATH`，找不到時請填絕對路徑。
- **參數與權限**：以 JSON 陣列填入額外啟動參數，例如 `["--model", "your-model"]`。略過權限確認的高風險模式預設關閉，必須逐一為 Agent 啟用。
- **歷史資料來源**：讀取歷史的資料夾。**偵測歷史來源**會檢查官方已知位置。

## Shell Profiles

設定新終端機使用的 Shell、參數與環境變數。

## 外觀與預設值

- **語言**：English、繁體中文，或跟隨系統語言。切換時會重新載入視窗，終端機會自動重新連線。
- 介面與終端主題、色系、字型，以及工作台縮放（<kbd>⌘</kbd><kbd>+</kbd>／<kbd>⌘</kbd><kbd>-</kbd>／<kbd>⌘</kbd><kbd>0</kbd>）。
- **新增工作**時預設的 Agent 與 Shell Profile，以及系統通知。
- **版本更新**：啟動時與每天一次檢查 GitHub Releases 是否有新版本。不會自動安裝更新。

## 提醒通知與音效

在**外觀與預設值**的**系統通知**區，可分別啟用系統通知與 **Agent 需要注意時播放音效**。音效預設關閉，舊設定也會採用此預設值。音量範圍是 0–100%（預設 70%），設為 0 即靜音。

等待播放提示音、完成播放輕音、失敗播放低音。所有音效皆以 Web Audio 合成，沒有隨附音檔。只有面板不在畫面上或視窗在背景時才提醒，每個面板共用 5 秒冷卻。跨面板的音效事件會收集 1.5 秒，再依 **等待 > 失敗 > 完成** 的優先順序播放一個音效；每個符合條件的面板仍會分別收到系統通知。啟用音效時，Linux 會送出 `suppress-sound` 提示，避免重複發聲；即使音量為零或勿擾已將程式內音效靜音，也會套用。Session Bay 的 Windows 通知本身就沒有聲音。

三個**測試**按鈕使用尚未儲存的音量，即使音效關閉也可試聽，且會略過可見狀態與兩種冷卻限制，但仍遵守已偵測到的勿擾模式。儲存設定後，音效開關與音量才會套用至 Agent 事件。如果 WebView 需要使用者操作才能播放，啟用音效後請在程式內點擊或按鍵；測試按鈕也會初始化音訊。

### 勿擾模式的限制

勿擾偵測採盡力而為方式。若不支援、偵測失敗或回傳無法辨識的結果，仍會照常播放音效，僅寫入偵錯紀錄。系統通知仍由作業系統的通知政策控制。

- **macOS — 不支援，API 選擇 UNVERIFIED（尚未驗證）**：已考慮 `INFocusStatusCenter`，但尚未確認 entitlement、授權與作業系統版本要求，因此未啟用專注模式偵測；程式內音效可能在專注模式期間播放。
- **Windows — 部分支援，API 選擇 UNVERIFIED（尚未驗證）**：查詢 `SHQueryUserNotificationState` 的安靜時間、簡報與忙碌／全螢幕狀態。尚未確認是否涵蓋專注輔助與所有新版勿擾模式，因此部分模式下仍可能播放音效。
- **Linux — 部分支援，API 選擇 UNVERIFIED（尚未驗證）**：GNOME 透過 `gsettings` 讀取 `org.gnome.desktop.notifications show-banners`；KDE 透過 `gdbus` 讀取通知服務的 `Inhibited` 屬性，依 `XDG_CURRENT_DESKTOP` 選擇目前桌面。其他桌面、缺少工具或服務、逾時、不支援的屬性，皆會回復正常播放。橫幅設定或服務抑制狀態只是勿擾模式的間接訊號。

**驗證狀態**：上述 API 選擇尚未以官方文件或實際作業系統行為驗證。尚未測試 macOS WKWebView、Windows WebView2 與 Linux WebKitGTK 在背景／最小化時的播放情況。目前使用 Web Audio，未加入 Rust 播放備援。須完成各平台測試，才能判斷是否需要改用 Rust 音訊後端。
