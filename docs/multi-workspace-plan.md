# 單一視窗多工作區規劃

更新：2026-10-24。狀態：**方向已確認，尚未實作／驗收**。本文件只記錄方案與交付門檻；方案比較 mockup 見設計畫布（私人連結，需由擁有者分享）。

## 問題與已確認方向

目前多個專案的 Terminal／Agent 可以同時在背景執行，但整個應用只有一個主視窗，中央只顯示目前選取專案的分頁；不同專案的工作無法同時看見。使用者不採用多視窗（需要在視窗間切換、較亂），要求在**一個視窗**內同時處理多個工作區。

比較四種方案後確認：

- **主要：總覽格狀檢視**——同時監看多個執行中的工作，需要操作時放大進入。
- **輔助：跨專案分割分頁**——偶爾需要兩、三個專案並排操作時使用，預設不混合。
- 全域分頁列（快速切換、不能同時看）與釘選面板（只適合一兩個固定面板）不作主要解法，可作後續小改進。
- 多視窗不採用。

## 總覽格狀檢視（主要）

- 一個特殊的「全部工作區」檢視，與一般工作分頁並存；不另開視窗。
- 每個執行中的 Terminal／Agent 一格：專案識別色與名稱縮寫、專案名稱、Agent／Shell 種類、分支、狀態（執行中／等待輸入／已結束與 exit code／失敗），以及最後數行輸出。
- 「等待輸入」最醒目，提供「放大並回覆」；任何格子都可放大成完整 Terminal 操作，再返回總覽。
- 依狀態、專案、Agent 篩選；格子依需要注意的程度排序可切換。
- 效能：格子不各自建立完整 xterm 實例，使用有界的文字尾端預覽；只有放大的那一格是互動 Terminal。數十個工作時仍需維持流暢，量測需附環境。
- 狀態只採用既有可靠來源（runtime 生命週期、hook 狀態），不把「程序存活」畫成「正在思考」。

## 跨專案分割分頁（輔助）

- 一般分頁維持單一專案；「混合分頁」需主動建立並在分頁上標示。
- 混合分頁中的每個面板保留自己的專案、cwd 與 runtime 身分；移入或移出不重啟程序。
- 辨識要求：
  - 每個專案有穩定識別色（可自訂），永遠搭配名稱縮寫，不只靠顏色。
  - 面板標頭永遠顯示「專案 · 分支 · 狀態」，空間不足也不收起。
  - 聚焦面板以加粗外框與專案色標示。
- 右側 Sessions／Files／Git 跟隨聚焦面板的專案，標題寫明專案名稱；切換時短暫提示，避免對錯誤 repo 做 commit、push、reset 等操作；這些操作的確認對話框強調目標 repo。
- 建議上限 2–3 個專案並排；更多時引導使用總覽。

## 架構影響與待決事項

- 目前每個分頁屬於單一專案（`tab.projectId`），面板本身已記錄 `projectId`；混合分頁需要調整分頁的專案歸屬、工作區保存格式與遷移，以及側欄「開啟中的工作區」的分組。
- 右側工具的專案 context 由「目前選取專案」改為「聚焦面板的專案」，需確認 Files／Git 的開啟文件如何歸屬。
- 鍵盤：進出總覽、在格子間移動、放大／返回的快捷鍵與焦點規則；IME 與 Terminal 輸入不得被攔截。
- 待決：專案識別色的配置與可及性對比、總覽排序預設、混合分頁的建立入口。
