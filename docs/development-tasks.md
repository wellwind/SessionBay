# Session Bay 完整功能與開發任務

整理日期：2026-10-15。目前尚未建立可執行應用，以下任務均未開始。交付主線為「選專案 → 找歷史 → 預覽 → 接續 Agent → 分割普通 Terminal」；完成 P0 才構成完整 MVP。

功能與驗收依據為[產品規格](product-spec.md)、[介面規格](ux-spec.md)、[架構](architecture.md)、[Agent 整合規格](agent-integrations.md)及[路線圖](roadmap.md)。技術組合與未定選項沿用[決策文件](decisions.md)的狀態，任務拆解不代表已核定選型或新增產品承諾。

## 任務使用方式

共 123 項任務，分為 17 個群組；以下數量是目前拆解層級，候選功能通過研究後還需補實作子任務。

| 範圍 | 任務數 | 排程原則 |
| --- | --- | --- |
| P0 決策、原型、功能與驗收 | 96 | 完成完整 MVP 所需 |
| 發行前交付 | 6 | 依選定平台與發布方式執行 |
| P1 工作脈絡與整合擴充 | 9 | 依試用結果確認順序與範圍 |
| P2 與待研究功能 | 12 | 先定義範圍，再排條件式實作 |

每列可建立一張 issue。「完成條件」是最低驗收要求，仍須滿足上游規格；「前置任務」列出直接相依，其餘依賴可向前追溯。`—` 表示沒有任務相依；`待範圍決策` 表示實作受研究結果約束。

- 狀態：`[ ]` 未完成，`[x]` 完成；進行中或受阻時，於對應 issue 記錄原因與負責人。
- 完成時附程式／文件變更、適用的測試或人工驗收結果；效能附環境、版本、日期與樣本數。
- 尚未估算工期；完成 PRE 與 SPIKE 後，再依選型、團隊與支援平台估算。表格順序不代表可以跳過相依任務。
- 新發現的工作新增穩定 ID，不重新編號；需求變更先更新決策與規格，再調整清單。
