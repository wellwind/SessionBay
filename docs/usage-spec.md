# Session Bay Agent 用量與分析規格

整理日期：2026-10-15。使用者已指定整組用量功能在 MVP 之後交付，列為 P1。目標是查看各 AI Agent 的使用情況，並在來源支援時依 Project、Agent、Session 下鑽；首批評估 Codex CLI 與 Claude Code CLI，其餘工具逐一新增能力。

## 功能與交付順序

| 功能 | 範圍 | 交付 |
| --- | --- | --- |
| F15 Agent 用量與額度總覽 | Agent／供應商／帳號／工作區 | 額度、剩餘量、重置時間、來源狀態及刷新 |
| F16 專案與 Session 用量分析 | Project／Agent／Session／模型／日期 | token、可用的請求數、費用估算、趨勢與來源明細 |

先完成來源能力與資料語意驗證，再交付 F15，接著交付 F16。兩者均不阻擋既有 P0 MVP。OpenUsage 作為功能參考；是否讀取其本機輸出由來源評估決定，不要求使用者安裝另一個應用才能使用基本能力。

## 指標定義

| 指標 | 意義 | 顯示與聚合規則 |
| --- | --- | --- |
| 帳號額度 | 供應商回報的短期、每週或其他配額窗口 | 保留窗口與單位，不固定假設每家都有相同窗口 |
| 剩餘量與重置時間 | credits、百分比、token 或來源提供的其他單位 | 僅對單一已知窗口計算剩餘量；不同帳號百分比不相加 |
| Token 用量 | 來源紀錄的輸入、輸出、cache 與 reasoning 欄位 | 保存原始語意，正規化後避免子集合重複相加 |
| 請求數 | 可唯一識別且符合來源定義的請求 | 不以訊息數或終端輸出行數替代，不可取得時顯示未知 |
| 來源回報費用 | 來源直接提供的金額 | 記錄來源是否為估算或帳務資料；CLI 回報不自動視為實際扣款 |
| 估算費用 | token 與可驗證價格規則計算的金額 | 標示估算、幣別、模型、價格版本與涵蓋範圍 |
| 實際帳單 | 供應商帳務介面的金額 | 僅顯示來源明確提供的範圍，無 Session 明細時不分攤 |

訂閱月費、包含額度的消耗、API 等值估算與額外付費分開顯示。不把 API 等值估算稱為訂閱方案已花費，也不將固定月費依 token 比例自動分攤。

帳號的額度窗口使用「短期額度」「每週額度」等名稱，避免與對話 Session 混淆。共享帳號額度可以出現在專案頁，但標示「帳號共享」，不聲稱是該專案專用的剩餘量。

## 已查核的來源能力與實作限制

以下是 2026-10-15 查閱的一手文件，尚未完成 Session Bay 的版本相容實測。

| 來源 | 已確認的參考能力 | 對 Session Bay 的限制 |
| --- | --- | --- |
| [OpenUsage](https://github.com/robinebers/openusage) | 額度窗口、credits 與本機紀錄推算的花費 | 參考其呈現方式，不把所有工具都當成可精確計費 |
| [Codex App Server](https://learn.chatgpt.com/docs/app-server) | `account/rateLimits/read`、帳號用量摘要、`thread/tokenUsage/updated` | 需核對支援版本、登入模式、通知範圍及歷史可用性，不假定涵蓋所有外部 CLI Session |
| [Codex 用量說明](https://learn.chatgpt.com/docs/pricing) | 官方 usage dashboard 與 CLI `/status` 可查看限制 | 作為人工比對入口，不向正在工作的 Terminal 注入 `/status` |
| [Claude Code Monitoring](https://code.claude.com/docs/en/monitoring-usage) | token／cost metrics、Session 屬性；cost 屬近似值 | OTel 不等於訂閱剩餘額度 API；新收集的 metrics 不自動補出歷史缺漏 |
| [OpenUsage Claude adapter](https://github.com/robinebers/openusage/blob/main/docs/providers/claude.md) | 使用既有登入取得訂閱額度的實作參考 | 屬工具實作，不能當成供應商公開穩定 API 或普遍授權能力 |
| [OpenUsage 本機 API](https://github.com/robinebers/openusage/blob/main/docs/local-http-api.md) | 本機額度快照輸出 | 可選來源；需核對 schema、身份與資料時間，不能直接當成 Session 事件 |

歷史分析優先評估現有 transcript／JSONL 中實際存在的 usage 欄位；欄位、事件語意及版本需以去識別 fixtures 驗證。只有帳號總額或累計值的來源，不承諾能還原每次請求、每天或每個專案。

## 瀏覽方式

### 全域用量

新增「用量」入口，提供兩個分開的檢視：

- **額度總覽**：依 Agent、供應商、帳號及工作區顯示可用窗口、已用／剩餘、重置時間與最後成功更新。
- **用量分析**：依日期範圍查詢 token、可用的請求數及費用，顯示時間趨勢與 Project × Agent 彙總表。

分析支援今天、近 7 天、近 30 天及自訂範圍，並可組合 Project、Agent、Session、模型與已確認的帳號篩選。統計範圍只包含已收集資料；帳號端摘要與本機事件分開呈現，不能直接相加。

### 專案用量

專案頁新增「用量」檢視，顯示該專案在所選期間的 Agent 分布、token、可計價部分及 Session 清單。點選 Agent 可縮小範圍，再點選 Session 查看事件與來源。未歸屬事件另列，不藏在合計中。

### Session 用量

歷史詳情新增用量區塊，顯示該 Session 的模型分布、token 類別、可用請求數、費用性質及資料完整性。可開啟對應對話位置核對；若只有 Session 累計總量，與日期範圍內事件用量分開顯示。

從 Session 進入分析時保留 Session／Project／Agent 條件，返回時保留原先搜尋狀態。用量瀏覽不啟動模型、不恢復 Session，也不消耗付費額度來做自我檢測。

## 歸屬與去重規則

1. Agent 工具、模型供應商、模型及帳號分開記錄；Claude Code 等工具使用其他 provider 時不混為同一帳號。
2. Session 以 agent、source、external ID 對應既有模型。Project 沿用既有分組，原始 cwd 不被 launch override 改寫；搬移目錄後不增加用量。
3. 帳號需有事件或來源層級的可靠身份，不能依「目前登入帳號」回填全部歷史。未知帳號／Project／Session 保留未歸屬。
4. 同一請求從本機檔、即時通知或 OTel 重複收集時，只保留一筆主要計量紀錄及其他來源引用。無法證明相同請求時，來源分開比較，不盲目合併。
5. 明列事件是單次 delta、Session 累計還是帳號期間合計。累計資料依穩定身份與 checkpoint 計算增量；重啟、歸零、改版與非單調修正需重算，不能逐筆加總累計值。
6. 恢復、重掃、封存、檔案替換與 fork 複製的歷史前綴不重複計費。父 Session 與子代理保留關係，父層已包含的總量不再加子層。
7. cache read／write 可能是輸入的子集合，reasoning 可能已在輸出中；adapter 須記錄包含關係。未知語意的欄位不組成假的統一總量。
8. 每次確實發生的計量請求按來源記錄；重試是否產生額外用量以可識別事件為準，不用失敗訊息數推算費用。
9. 專案重新分組時更新聚合，不複製事件。單一 Session 中途換 cwd 時預設沿用 Session 專案，保留事件 cwd；跨專案逐事件分攤需另定規則。

## 時間與資料完整性

事件保存 UTC 時間，按使用者選定時區顯示與分桶；今天及自訂區間採明確起訖邊界，測試跨日、時區與日光節約切換。額度窗口依供應商重置時間呈現，不用本機午夜代替。

沒有可靠事件時間的累計值不塞入某天的趨勢。可顯示「Session 累計，無法分日」；只有日期粒度的帳號摘要不聲稱可精確換算另一時區的逐日明細。

每個檢視顯示來源、收集範圍、最後成功更新及完整性：

| 狀態 | 顯示與操作 |
| --- | --- |
| 有資料 | 顯示計量值、單位及來源時間 |
| 部分資料 | 顯示已知小計、缺少哪些欄位及無法定價的用量 |
| 未知／未支援 | 顯示原因；零僅代表來源明確回報為零 |
| 已過期／離線 | 保留最近值及原時間，標示過期，允許手動刷新 |
| 未登入／權限不足 | 引導使用受支援的登入方式，保留本機可用的 token 分析 |
| 來源衝突／未歸屬 | 保留各來源及歧義，提供檢視，不猜測填補 |

未知模型價格不影響已知 token 的呈現。費用可顯示「已定價部分小計」及未定價 token／事件數；只有所有必要資料完整時才稱為該範圍合計。不同幣別分列，未來若換匯需另附匯率來源及日期。

## 儲存與收集架構

帳號額度與用量事件採不同資料表及聚合路徑：

| 實體 | 主要欄位與責任 |
| --- | --- |
| UsageAccount | provider、外部帳號／工作區身份、本機別名；憑證僅存安全儲存區引用 |
| QuotaSnapshot | account、bucket ID、窗口、單位、used／limit／remaining、resetsAt、來源及觀測時間 |
| UsageEvent | 穩定事件／請求鍵、來源 locator、agent、provider、account／project／session、model、cwd、時間與計量語意 |
| UsageMeasurement | 原始 token 欄位、包含關係、正規化值、來源金額及其性質、完整性 |
| PricingRule | provider／model、價格項目、幣別、生效區間、來源及版本 |
| UsageAggregate | 依期間與維度產生的可重建彙總，包含未歸屬與未定價數量 |

歷史 adapter 額外輸出可用 usage 事件；額度 collector 只讀帳號快照。候選來源為官方介面、唯讀本機紀錄及選用的本機 OTel／OpenUsage 輸出，來源能力分別標示。

收集工作使用受控排程、取消、timeout、去重與退避；先呈現本機快取，再刷新。刷新頻率與保留期間在來源驗證後決定；手動刷新不能造成重複背景工作或頻繁打擾登入。用量處理不阻塞 PTY、既有索引或搜尋。

價格使用版本化規則與明確模型映射，未知別名不模糊猜價。歷史費用使用當時適用且可驗證的價格；若只有目前價格，可提供另標示的重估值，不覆寫既有估算。保存價格依據，讓相同資料可重現結果。

## 權限與本機資料

- 用量查詢採使用者啟用的受支援來源。需要帳號連線時，說明讀取範圍；憑證留在 OS 安全儲存區，不進 SQLite、日誌、匯出或版控。
- 不修改原 CLI 的憑證、設定或 transcript；到期登入交回原工具或受支援登入流程，不模仿其他應用私有 token rotation。
- 選用 OTel 僅在使用者啟用後，對受管的新程序設定必要環境；使用本機接收與欄位白名單，避免收集 prompt、回覆、工具正文及不必要身份資訊。
- 額度查詢只聯絡對應供應商；本機用量分析不將對話或路徑送到外部。價格更新與額度查詢分別列出網路目的。
- 關閉來源停止刷新；移除來源／帳號及清除用量時同步清理事件、快照與聚合。索引重建保留自有筆記及可重建來源，明確區分重建與刪除。
- 若與 OpenUsage 互通，僅讀取使用者指定的本機輸出，驗證 schema 與來源身份；不繼承其憑證處理或資料上傳行為。

## 驗收條件

F15 須通過多帳號／多窗口、明確零值、未知值、憑證到期、離線、過期快取、限流與刷新取消等案例；缺少額度來源時可降級，其他 Agent 與 Terminal 不受影響。

F16 須以可重複資料驗證 Project → Agent → Session 下鑽與交叉篩選。各維度的小計、未歸屬部分及全域已知事件總量一致；帳號百分比及未確定重疊的來源不加入事件總量。

資料測試涵蓋累計值重播、去重、cache／reasoning 包含關係、重試、resume、fork、子代理、來源刪除、索引重建、時區邊界及未知價格。效能驗證在背景刷新／彙總時仍符合既有 Terminal 與搜尋驗收，另記錄用量查詢的延遲與資料規模。

開發任務見[USG 任務群組](development-tasks.md#p1-agent-用量與分析)。
