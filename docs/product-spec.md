# Session Bay 產品功能規格

本規格定義建議 MVP 的可觀察行為與驗收條件。P0 是第一版完整工作恢復流程的必要範圍；P1、P2 原規劃在 MVP 後交付或評估；使用者追加並提前實作的功能，以[後續待辦](future-backlog.md)的逐項狀態為準。其中 F15、F16 用量功能的交付階段已由使用者指定為 P1。

2026-10-16 平台要求：Windows／macOS／Linux 原生可用性獨立於目錄 dialog PR；平台與 CLI 支援不等同原生驗收通過，驗收門檻見[三平台支援](platform-support.md)。

## 名詞與實體

| 名詞 | 定義 |
| --- | --- |
| Project | 以工作目錄識別的 catalog 分組；`curated` 表示是否由使用者選入左側專案，與歷史存在及工作區是否開啟分開 |
| 所有目錄 | 獨立導覽頁，列出所有 `sessionCount > 0` 的目錄分組，包含未知／失效路徑，不以自選專案資格限縮 |
| 專案（Projects） | 預設首頁，以總覽與側欄管理使用者明確加入的目錄，可包含沒有歷史的目錄 |
| Agent installation | 一個工具的可執行檔、版本與資料來源設定 |
| Session | Agent 保存的歷史對話，不代表仍有程序執行 |
| Runtime | 應用管理的 PTY 與子程序，具有啟動、執行、退出等狀態 |
| Workspace tab | 專案內的一個工作區分頁，可以包含多個面板 |
| Pane | 顯示 Agent Terminal 或普通 Terminal 的單位 |
| Transcript | Session 的對話紀錄；與 Terminal 當前畫面緩衝不同 |

## F01 工具偵測與資料來源設定

2026-10-15 追加後，啟動範圍為 Codex CLI、Claude Code CLI、Grok Build、Antigravity CLI（`agy`），並於 2026-10-16 追加 OpenCode。五者均有歷史 adapter；Antigravity 限 CLI 的已觀察持久化格式，1.3.5 真實樣本驗證另列，不涵蓋 App／IDE。透過已知 adapter 偵測工具與歷史位置；提供手動指定執行檔與受支援資料目錄。設定選擇器提供五工具，不依是否曾啟動、是否安裝或是否已有來源而移除選項；僅展開選中工具的配置與歷史能力卡片；各工具分開顯示「可啟動」、「歷史支援」、「來源未設定／停用／缺失」及索引健康。前後端使用共用 provider manifest，實際 parser 與驗證仍為內建型別分派，尚非動態外掛機制。安裝／版本重新偵測與歷史重新掃描是不同動作，使用已保存設定。

驗收條件：

- 工具已移除但歷史仍在時，可以搜尋與預覽；恢復動作提示指定執行檔。
- 工具有安裝但沒有歷史時，可開始新工作，不顯示掃描失敗。
- 自訂資料位置與多個來源可被識別，不能直接合併不同來源的同名 Session ID。
- 不聲稱能自動識別所有 AI 工具；未支援工具顯示能力邊界。
- 升級不改既有來源 ID、root 或 enabled，不自動新增 Grok 根目錄。缺少 Grok 來源時可新增草稿，填入絕對路徑後明確保存才生效；不猜測使用者 home。
- Antigravity CLI 能力卡片提供來源偵測、草稿新增、歷史列表與預覽；已知格式不代表所有版本均已驗證。備份來源僅預覽，索引接續限目前 HOME 的原生 CLI store，理由以每筆 Session 能力表示。

## F02 專案總覽與目錄分組

歷史依紀錄中的工作目錄分組。預設「專案」首頁的總覽卡片與側欄只顯示使用者明確加入的目錄；獨立「所有目錄」頁的總覽與側欄則顯示全部 `sessionCount > 0` 分組，包含已加入、未加入、失效及未知目錄。兩頁都先選組才顯示該組歷史，不以平面混合 Session 清單取代總覽。顯示名稱、完整路徑、最近活動、Agent 類型與 Session 數；支援搜尋與顯示名稱；專案清單改為持久拖曳自訂排序，提供排序把手與 Alt＋上／下鍵盤替代操作，不再顯示上／下移按鈕，首次承接舊版置頂／活動順序並移除置頂介面；所有目錄維持探索排序。「移出專案」才取消會員資格。側欄專案／目錄清單與開啟中的工作區可獨立收合，記住狀態且不關閉程序。掃描新來源、補掃、索引重建均不得自動增加側欄專案。

「加入既有目錄」接受已存在目錄的絕對路徑與可選顯示名稱；沒有歷史也可加入。「建立新專案」接受已存在父目錄的絕對路徑及單一新資料夾名稱，建立成功後加入專案。歷史預覽另提供「加入專案」，把可用的已發現目錄明確加入。本機目錄欄位可使用系統資料夾選擇器，並保留手動絕對路徑輸入。選取只回填草稿，仍需明確提交並通過既有後端驗證；取消不改動草稿。

驗收條件：

- 相同目錄中的不同 Agent 出現在同一專案。
- 名稱相同、路徑不同的專案可以清楚區分。
- 自動發現的工作階段即使未加入專案，仍可在所有目錄選組後搜尋、預覽及按既有預檢規則接續；未加入不表示掃描失敗。
- 加入、名稱與釘選跨重開保存；schema 升級將舊版手動加入或釘選項保留為自選專案，其餘自動發現項維持未加入。
- 重複加入同一 canonical 目錄不產生重複專案；背景掃描不得清除加入狀態或覆寫自訂名稱。
- 建立新專案拒絕空名稱、`.`、`..`、多層路徑與既有目標；不覆寫檔案或目錄，不建立不存在的祖先目錄。失敗應保留輸入並顯示可修正原因。
- 從專案移出只清除 `curated` 與釘選，不刪除檔案、歷史、索引或工作區，也不停止任何 Runtime；後續掃描不得再次自動加入。
- 未加入或移出專案但已開啟的工作區在兩頁皆有獨立入口，不因整理側欄而無法切回。
- 失效目錄仍可查看歷史；恢復前可選擇重新定位目錄。
- 重新定位保留原始紀錄路徑與 cwd，不修改來源 transcript。
- cwd 缺失的紀錄進入「未分類」，不猜測成目前工作目錄。
- symbolic link、大小寫與 worktree 的合併採明確規則，詳見整合規格。

## F03 跨 Agent Session 清單

選擇專案或目錄後，該組工作階段依最後活動時間排序，顯示 Agent、標題或替代標籤、時間、工作目錄與封存標記；分頁載入。支援該組內的文字、Agent、日期與封存狀態篩選。所有目錄的分組完整性不受專案加入狀態影響，既有封存及子代理顯示規則不變；尚未選組的總覽不載入跨目錄 Session 清單。

驗收條件：

- 優先使用原工具提供的名稱／標題；缺少時使用首則實際工作需求片段，略過開頭的 AGENTS.md 指令、環境上下文與中斷通知，仍缺失則使用短 ID。
- 自訂名稱不被後續壓縮摘要覆蓋；來源改名可在更新索引後反映，名稱不作唯一鍵或替代恢復 ID。
- 清楚標示可搜尋的資料範圍、索引中與解析不完整狀態。
- 子代理與分支保留來源關係；預設不把每個子代理列成獨立主工作。
- 檔案修改時間只能作為活動時間的 fallback，不能假裝是對話事件時間。

## F04 搜尋與對話預覽

MVP 提供標題、使用者訊息與 agent 回覆的關鍵字搜尋。工具輸出內容的全文索引列為後續可選項，避免大量建置日誌淹沒結果。搜尋結果提供命中片段、Agent、專案與時間。

預覽優先顯示最近對話、最後的使用者要求及 agent 回覆；可以展開更早內容。完整內容按需讀取，與 Terminal 畫面分開呈現。

驗收條件：

- 在所選目錄跨 Codex、Claude Code、Grok Build、Antigravity CLI 的可索引歷史搜尋，另可明確開啟跨目錄全域搜尋。Antigravity 只索引防禦 reader 可辨識的官方 transcript.jsonl 正文，metadata-only／full-only 不假造正文；CLI 1.3.5 的真實格式與接續驗收仍見 [相容性限制](antigravity-cli-history.md)，不把可啟動狀態當作版本驗證。
- 所有目錄保留未加入、已移出及 cwd 缺失分組；選組後可搜尋其可索引歷史。釘選與加入只改變導覽，不刪除或隱藏這些分組。
- 中文、英文與程式碼識別字具有可說明的匹配規則；中文搜尋是 MVP 驗證項目。
- 若結果來自尚未更新的索引，能顯示來源已變更並重新載入。
- 長對話分段讀取，附件、壓縮與不支援事件有占位說明。
- 搜尋或預覽不會啟動 Agent，也不會把內容送到模型服務。
- 搜尋快捷鍵回到目前所選目錄的歷史並聚焦輸入，不清掉目錄範圍；未選組時主動使用搜尋快捷鍵或全域搜尋入口才顯示跨目錄結果，不取代預設分組總覽。

## F05 恢復 Session 與開始新工作

恢復前檢查工具、來源紀錄與目錄。使用原 CLI 的恢復能力在 PTY 中執行；透過參數陣列與獨立 cwd 傳入，不組合任意 Shell 指令字串。

驗收條件：

- 點選恢復後，在對應專案開啟或聚焦 Agent 面板。
- 同一 Session 已由本應用開啟時，預設聚焦既有面板；另開副本需明確操作與工具支援。
- 對應程序已在外部執行但無法確認附接能力時，提示狀態未知，不任意中止外部程序。
- CLI 恢復失敗時保留錯誤訊息，允許重新指定工具、工作目錄或改開新 Session。
- 成功啟動程序不代表已成功載入歷史；未取得可靠訊號時，顯示「已啟動，待確認 Session」。
- 新工作沿用專案目錄；先選 Agent 或普通 Shell，再以帶標誌的登錄下拉清單選 Agent，不為每個工具新增頂層分頁。
- 從所有目錄選組後直接接續未加入專案的 Session，不隱含加入專案；仍使用原始 cwd 或既有重新定位規則。
- 沿用 Agent 本身的登入；預設不追加跳過權限旗標。每個 Agent 可各自保存參數及明確勾選的高風險模式，保存後不在每次啟動重複確認；CLI 自身政策仍可能要求操作。
- 啟動預覽與真正啟動共用後端計畫，顯示精確 executable、argv 與 cwd；預覽不啟動程序，真正啟動重新預檢。自訂參數不可覆蓋應用管理的 cwd、來源或 Session 身份。
- Grok／Antigravity 可輸入手動 `resumeId`，不可與索引 `sessionId` 混用；手動 ID 不建立虛構歷史關聯。多 Grok 來源的歧義須阻擋，Antigravity 只保證按正式 CLI 參數發起接續。
- 危險模式按工具語意說明：Codex 預設取消審批與沙箱；Grok 自動核准與沙箱分開。危險自訂選項必須經 opt-in；明確自訂權限模式不被通用預設覆蓋。

## F06 普通 Terminal

提供預設 Shell、Profiles、鍵盤輸入、中文輸入法、複製貼上、捲動、搜尋、調整大小與程序退出顯示。可從專案直接開啟，也可選其他目錄。

相容性至少驗證目標平台上的 Shell、Codex、Claude Code、互動式提示、Vim；macOS 或 Linux 另驗證 tmux。進階圖片與鍵盤協定按需求追加。

普通 Terminal 裡手動執行 Agent 時，仍維持普通面板。除非取得可靠 Session ID 或使用者明確建立關聯，不自動轉成已關聯的 Agent 面板。

普通 Shell 經 broker 確認以結束碼 `0` 正常退出後自動移除面板，最後一個面板退出則關閉分頁；專案與全域臨時 Terminal、背景分頁及重新附接皆適用。新建 Agent、非零或未知結束碼、失敗、斷線與中斷狀態保留面板供檢視。接續 Agent 以啟動來源標記確認後，正常退出採相同清理；普通 Terminal 內手動啟動 Agent 退出後回原 Shell。僅還原布局的 placeholder 不會自動移除。

Shell 設定另驗收：全新預設選有效絕對 `$SHELL`，否則 macOS `/bin/zsh`、Linux `/bin/bash`，args `[-l]`；不匯入 Terminal Profiles 或 rc。重新偵測只回傳候選，使用者明確加入／保存，保留既有自訂 Profiles 與預設項。Shell 啟動檔由 Shell 本身載入。

全域臨時 Terminal 補充：無任何專案時也能從頂列開啟，Rust 決定家目錄，採 null project 身分，不新增 catalog／假專案。多分頁、切頁找回、UI 關閉重開附接及明確關閉單一 Runtime 的驗收見[獨立規格](temporary-terminal.md)。

## F07 工作區分頁與分割面板

結構為 Project → Workspace tab → Pane。單一分頁可只有一個面板，也可以左右或上下分割，混用 Agent 與普通 Terminal。

驗收條件：

- 至少兩個 Terminal 可同時可見並持續執行，各有獨立 PTY。
- 可以拖曳調整比例、切換焦點、暫時最大化與還原面板。
- 改變尺寸後依實際字元尺寸更新 PTY 行列數。
- 切換分頁不會重啟或結束背景程序；輸出維持順序且緩衝有上限。
- 不提供預設廣播輸入，以免命令被送到其他專案。
- MVP 的明確關閉面板會結束其受管程序並移除視圖；執行中顯示一次明確確認。普通 Shell 正常退出依 F06 自動移除，新建 Agent 與異常退出保留最後畫面供檢視。
- 隱藏側欄、切換分頁、暫時最大化均屬視圖操作，不等於關閉程序。
- 從專案移出也屬導覽操作；保留已開啟工作區入口及其受管程序，僅明確關閉操作會觸發關閉流程。

## F08 基本客製化與布局保存

MVP 支援亮暗主題、終端色票、字型與大小、快捷鍵、Shell Profiles、預設 Agent、每個 Agent 的參數及危險模式 opt-in，以及工作區布局保存。設定須有版本與驗證，快捷鍵衝突可見。

獨立主題擴充提供 UI 深／淺色各 10 種與 Terminal 深／淺色各 10 種，可各自搭配。工具列快切立即套用並保存；設定內立即預覽，儲存成功才保留，取消／捨棄回復。純外觀儲存不受背景索引阻擋，來源變更仍受原有索引鎖保護。詳細行為與尚未完成的原生驗收見 [主題預覽](theme-preview.md)。

舊設定缺少新增 Agent 執行檔或選項時補上預設值；空參數與未勾選危險模式不改變既有使用者的權限選擇。五工具設定互不污染，無效參數／未知旗標由後端拒絕；設定欄位不儲存登入憑證。

重開應用恢復專案與布局，並以 broker 的 metadata 找回原受管 Runtime；不自動重新執行先前任意 Shell 指令。broker／電腦重啟後顯示 interrupted，提供明確恢復入口。程序生命週期另見 F13 與[持續 Runtime](persistent-runtime.md)。

## F09 增量索引與錯誤處理

先讀本機索引，再背景同步來源；提供掃描進度、取消、重新掃描與清除索引。清除索引不刪除原始歷史。

驗收條件：

- 容忍 JSONL 尚未寫完的尾行與無法解析的單筆事件。
- 支援檔案追加、截斷、替換、刪除與封存移動。
- 單一來源錯誤不阻擋其他來源與 Terminal 操作。
- 資料來源被刪除時，相關搜尋內容不永久殘留；已啟用 Agent 偵測後清理衍生索引，停用 Agent 的快取保留至重新啟用掃描或明確清除／重建。
- 不修改原 Agent 的 transcript、SQLite 或設定檔。

## F15 Agent 用量與帳號額度總覽

MVP 後新增「用量」入口，依 Agent、供應商、帳號／工作區顯示可取得的額度、剩餘量、重置時間與更新狀態；首批評估 Codex CLI、Claude Code CLI。各來源的窗口與單位分開呈現，不要求所有 Agent 提供相同指標。

驗收條件：

- 分別標示來源、最後成功更新、過期／未登入／不支援；未知不顯示為零。
- 支援手動與背景刷新；單一來源錯誤不阻擋其他 Agent、搜尋或 Terminal。
- 帳號共享額度不按專案分攤，不把窗口的「Session」誤稱為對話 Session。
- 不修改原 Agent 登入資料，不向工作中的 Terminal 注入查詢命令。

## F16 Project／Agent／Session 用量分析

MVP 後依來源可用程度，提供 token、可識別請求數、來源回報金額與可追溯的費用估算；可依 Project、Agent、Session、模型及日期篩選，從專案下鑽至 Session。

驗收條件：

- 保留來源身份與計量語意；缺少可靠歸屬的事件列為未歸屬，不依目前帳號或 prompt 猜測。
- 支援累計值、重播、resume、fork、子代理與多來源去重；cache／reasoning 子集合不重複加總。
- token、帳號額度、API 等值估算、訂閱月費及實際帳單分開；價格未知仍顯示 token 與未定價範圍。
- 日期範圍採明確時區及邊界；僅有 Session 累計且缺時間的數據不假裝可分日。
- Project／Agent／Session 彙總與已知事件一致；可回查來源，清除來源同步移除衍生用量。

詳細指標、來源限制與驗收見[Agent 用量與分析規格](usage-spec.md)。整組 F15、F16 不納入 P0 MVP。

## 其他後續功能

P1 除 F15、F16 用量功能，另包含手動工作狀態、Session 別名、接續筆記、Repo 分組、摘要與可預覽的跨 Agent 交接。手動狀態與程序狀態分開；Agent 停止輸出不表示任務完成。

獨立 broker 與重新附接已提升為最高優先並有實作，原生驗收仍待完成；P2 保留自動派工、同步與外掛。外掛能力、遠端 SSH 管理、Shell integration、圖片協定等，需另訂規格與優先序。

## 整體驗收

使用者能在同一專案找到不同 Agent 的歷史，預覽並恢復正確 Session，再分割出普通 Terminal 執行測試；索引同步與大量輸出時，仍可輸入、切換面板與搜尋。效能的量測方法與暫定門檻見[開發路線圖](roadmap.md)。

## 2026-10-16 持續 Runtime 變更

關閉 UI 不停止已開 Shell／Agent；重開須列出每個已開分頁／面板／專案狀態，附接相同受管程序並還原有界畫面。明確 Stop／關閉面板才結束程序。Broker／電腦重啟後以 interrupted 呈現，不得採用舊 PID 或自動執行指令。此規則取代本文件先前的 close-to-stop MVP 限制；驗收與已知終端限制見[持續執行](persistent-runtime.md)。

## Agent 圖片輸入增量

驗收要求：聚焦本機已知 Agent 支援 PNG／JPEG drop 與 paste，不自動送出，文字不重複貼上，目標切換取消，保留路徑可供恢復工作階段使用。不支援的 provider／格式須明確回饋；平台驗收不得以 mock 測試替代。詳細邊界與待驗收項目見 [圖片輸入](image-input.md)。

### Agent 啟用偏好

來源與工具設定按 Agent 選擇顯示，支援名稱搜尋；啟用開關與歷史來源開關獨立。設定保存前不影響執行與索引，取消不得遺留啟用狀態修改。舊設定及新加入 provider 預設啟用，未知 provider 偏好可往返保存。停用後禁止新的 Agent 程序與接續，暫停該 provider 歷史掃描；保留原始歷史、已索引歷史、配置與現有程序的附接能力。明確清除／重建索引不受快取保留規則限制。全部 Agent 停用不影響 Shell。

## 可復原刪除 Session（2026-10-17）

- 對話預覽提供「刪除 Session」，確認後移入資源回收筒，從一般歷史、搜尋與專案計數隱藏。
- 成功後可立即復原；全域資源回收筒提供逐筆還原、來源與移入時間。來源無法確認時顯示明確原因並保留項目。
- 重新掃描、Clear／Rebuild 索引及重新啟動不會讓已刪除項目重新出現；來源 ID 指向不同 canonical root 不會誤隱藏新來源。
- 原始 Agent 歷史及執行中的 Agent 完全不變。此階段不提供原始歷史永久刪除或清空回收筒。

## Agent 狀態總覽（2026-10-17 追加）

側欄提供每個專案的已開啟／存活／已結束／程序中斷數量，並另外列出連線中斷、失敗及尚未啟動；全域工作階段獨立顯示。展開專案可查看各 Runtime 的生命週期並回到對應面板。已開啟數包含保留的結束面板與尚未啟動面板；Runtime ID 去重，Shell 與歷史 Session 均不計入。停用 Agent 不改變既有程序的統計。

只採用 broker 與既有 Terminal 事件。連線中斷時存活未知，不能當作 exit 或 interrupted。活著的程序不等於正在工作，尚無可靠 Agent 活動事件時明確顯示活動未知。非目前專案也持續更新，不增加輪詢／掃描／CPU 探測。
